# 26. OEE = 완료 사이클 행의 집합 + '진행 중' 상태 (2026-09-08)

## 1. 배경

2026-09-08 현장(3000) #121_O/Y/Q 의 3시간 43분 정지가 비생산(24.5×CT 이상) 임계를 넘고도 '고장'으로 남았다. 원인은
무가동 상태머신(OeeDowntimeStateMachine)이 **행 밖에서** 만든 시간 소스였다:

- 상태머신은 분기를 모르고 부모 이름("#121")으로 무가동 이벤트를 쓴다. 정지 로그에는 같은 정지가 `#121`(무가동)과
  `#121_O/Y/Q`(이상치 초과 사이클)로 두 번 뜨고 이름이 달라 병합되지 않았다.
- 부모 이벤트 #1062(9/7 20:56 → 9/8 08:38)가 사이클이 도는 중에도 닫히지 않았고, 그 자세(midCycle) 도장이 분기 창
  전부에 "자기 유발자" 증거로 흘러들어 길이와 무관하게 고장으로 잠갔다.
- 이벤트는 라이브로만 생성되어 head/tail 재도출로 복원되지 않는다. 임계를 바꿔도 과거 판정이 함께 움직이지 않았다.

## 2. 원칙

**OEE 는 완료된 사이클 행(dspFlowHistory)의 집합에 대한 집계다.** 시간축은 사이클 행이 빈틈없이 타일링한다
(ct = 다음 head 까지의 주기). 남는 것은 flow 마다 열린 사이클 1개(진행 중)와 첫 사이클 이전 구간뿐이다.

행 하나 = (flow, 분기, 구간 [끝−ct, 끝], mt, wt). 행 밖의 시간 소스는 없다.

| 라벨 | 근거 | 성격 |
|---|---|---|
| 정상 | ct ≤ 평균CT × 비가동 배수, mt ≤ MT 경계 | 행 자체 |
| 비가동(고장/유지보수) | ct 또는 mt 초과 + 유발자 증거 | 행 + 형제 행 + 신호 |
| 대기 | 초과인데 유발자가 다른 설비 | 형제 행 |
| 비생산 | 초과 + 임계 이상 + 유발자 없음 / 지정 시각대 / 수동 | 행 + 설정 + 사용자 |
| **진행 중** | 열린 사이클(마지막 완료 사이클 이후 다음 head 없음) | 행 없음 — 유일한 예외, 분모 밖 |
| 미계측 | 심박 공백과 겹친 부분 | 카빙만 |

유발자 증거도 행에서 나온다:

- `mt > 중앙MT × 고장배수` = MT 과주행(유발자).
- `mt IS NULL` 이고 ct 가 비가동 경계 초과 = tail 을 못 마친 채 멈춤(일감을 쥔 자세, 유발자). **MT 기준(중앙 MT)이
  없는 flow(tail 미정의 → mt 항상 NULL)는 증거로 쓰지 않는다** — 안 그러면 그 flow 의 모든 장기 정지가 무조건 고장이
  되어 비생산 승격이 죽는다.
- `mt 정상 · ct 초과` = WT 정지(여파 또는 라인 정지 후보) → doc/25 신호 분류.

## 3. '진행 중' 상태

- 정의: flow 별 `[max(마지막 recordedAt, 창 시작), min(지금, 창 끝))`. 단, 창 끝(To) 이후 기록된 행이 하나라도 있으면
  창 끝 시점의 사이클은 이미 완료된 것(경계 사이클)이라 진행 중이 아니다. → **과거 창엔 항상 0**.
- 카빙 사슬: 미계측 ▸ 비생산(지정 시각대·확정) ▸ 형제가동 ▸ **진행 중** ▸ 비가동. 진행 중은 가용성 A 의 분자·분모
  어디에도 들어가지 않는다(미계측과 같은 자리).
- 부모(물리 설비) 축으로 잰다. 열린 사이클의 분기 소속은 완료·반증 창이 지나야 정해진다.
- 노출: `OeeSummaryDto.InProgressWallMs`, `OeeTeepDto.InProgressMs`, `OeeDailySlotDto.InProgressMs`,
  정지 로그 합성 행 `detectSource='in-progress'`(status=open, classifySource='pending', 정지 기준 초과분만, 설비당 1행).
- UI: 설비효율 정산 값 줄 "진행 중 n분 · 분모 밖·미확정", TEEP 시간 분해 옅은 회색 솔리드 세그먼트, 시간별 추이
  '진행 중' 데이터셋, 정지 로그 '진행 중' 행(구분·재분류·마감 대상 아님).

## 4. 제거된 것

- `OeeDowntimeStateMachine`(무가동 이벤트 INSERT/CLOSE/자세 도장/휴리스틱 분류) — 삭제. 라이브 정지 배지는 엔진 상태
  (FlowMetrics)가 이미 담당하므로 대체 불필요.
- 집계의 무사이클 갭 패스(oeeDowntimeEvent 기반 시간 적립)와 `GetNocycleIntervalsByFlowAsync` — 삭제. 정지 시간은
  이상치 초과 사이클 행에 이미 들어 있다.
- `OeeMath.ResolveNoCycleActions`, `ClassifyByDuration`, `AutoClassifyFailureMs` 와 해당 테스트.
- 비생산 자동 패턴 학습의 무가동 이벤트 입력(`CollectNocycleStopsAsync`) — 완료 행만으로 충분.
- `IOeeRepository.SetDowntimeMidCycleAsync / AutoClassifyHeuristicAsync`.

## 5. 기존 데이터

- `detectSource='nocycle'` 이고 `classifySource<>'manual'` 인 행은 부팅 시 삭제(멱등). 어디에서도 읽히지 않는 죽은
  데이터이며 원시(plcTagLog)에서 재도출되는 사이클 행이 같은 시간을 담고 있다. 정지 로그 조회도 이 조건으로 한 번 더
  걸러 미러/경합 잔존을 방어한다.
- 사용자가 손으로 확정한 행(`classifySource='manual'` — 비생산/유지보수 지정)은 사용자 의도라 보존한다. 집계는 이미
  구간 오버라이드(`GetManualReclassIntervalsAsync`, 유지보수 구간)로 읽고 있어 그대로 작동한다.
- `midCycle` 컬럼은 스키마에 남는다(읽는 곳 없음).

## 6. 재연산 규약

- head/tail 변경 → `CycleRecomputeService` 가 구간 DELETE+INSERT → 미러 재복제 → `OeeChangeSignal.Notify` → 집계 L1
  캐시(10초 TTL)·사전계산이 새 행으로 재계산. 모든 화면이 같은 행을 보므로 행이 바뀌면 전부 따라온다.
- 오늘 수치는 열린 사이클이 완료되는 순간 바뀐다(진행 중 → 확정). 의도된 동작.
- 집계 캐시 키 버전 v30.

## 7. 남은 결정

- 형제 설비 사이클이 아직 진행 중일 때 내 완료 행의 고장/대기 라벨은 잠정이다(조회마다 재계산으로 수렴). "잠정" 표시는
  미구현.
- 정지 로그의 수동 재분류 저장 키는 여전히 이벤트 id/materialize 구간이다. 경계가 크게 밀리는 재도출 뒤 수동 라벨의
  겹침 재부착 관대화는 후속.
