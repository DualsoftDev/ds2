①왜 확장 · 자동화 원칙

현재 한계 — P5는 설비 단위 OEE만 자동, 정보 범위 좁음. 라인·WO·시프트 관점 부재.
  • 원칙 1 — P5에서 확정 자동계산된 값만 재활용 (실측/비가동 CT · A · P · MTTR/MTBF)
  • 원칙 2 — 품질(Q)은 자동 불가 — P5와 동일 수기 입력 ✎ 수기
  • 원칙 3 — Top = TEEP (24×365 풀가동 기준). 여기서 레벨다운(OEE → A/P/Q → Cycle)
  • 원칙 4 — 확장 신호(Recipe·Batch·PV·Alarm 세부)는 사업장별 편차 커서 표준 확장 대상 제외
  • 원칙 5 — 모든 상위 지표는 P5 자동 산출값의 재조합. 새 PLC 태그 요구 없음
🎯 목표 — 최상위는 24×365 캘린더 풀가동(TEEP)에서 시작, 클릭 한 번씩 아래로 내려가며 OEE→A/P/Q→Cycle을 자동 정합 재집계.

⑥구현 순서 (P5 위에 확장)

  • ① P5 산출 재활용 — Σ실측CT · Σ비가동CT · Cycle 수 · A · P · MTTR · MTBF 그대로 사용
  • ② 기간 필터 인프라 — 연·월·주·일·시프트 기준 자동 재집계 (P5는 사이클/이벤트 원본 보존)
  • ③ 대상 필터 인프라 — 전사·라인·설비 계층 (기존 P5 asset 계층 재활용)
  • ④ TEEP 계산 순수함수 — TEEP = ΣMT ÷ 캘린더시간, Utilization × OEE 분해 검증
  • ⑤ Q 수기 그대로 — P5 동일. 향후 자동화 여지 있으면 별도 트랙
  • ⑥ UI L0 상단 — /app/dashboard.html은 TEEP Hero, 클릭 시 L1 OEE, L2, L3(P5 uptime.html)로 전이
  • ⑦ 레벨 정합 검증 — 하위 재집계 결과가 상위 값과 수치 일치하는지 자동 assert

⑦비목표 · 가정

  • 확장 신호 자동화 배제 — Recipe·Batch·Prod Counter·PV·Alarm 세부 코드는 사업장별 편차 커서 표준 배제
  • 품질 Q 자동화 불가 — P5와 동일 수기 유지. 향후 표준화되면 재검토
  • 계획 정지 분리 — 계획정지 캘린더가 없으면 TEEP=Utilization×OEE 분해 대신 단일 값만 제공
  • CT이상치 14일 평균 정책 — P5와 동일. 확장 지표도 동일 소스 사용
  • 레벨 간 정합 — 하위 재집계값 = 상위 값이 성립해야 함. 이상 시 상위에 경고 배지
  • 육안·수기 로그 — 자동 커버 불가, 별도 트랙
