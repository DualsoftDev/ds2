# DS 모델 도메인 배경

## 파일 임포트 (2026-06)
- mermaid 확장자 = **`.mmd`** (`.md` 호환 유지, 신규는 `.mmd`)
- 임포트 진입점 = **파일 → 열기** 단일 경로. Flow/Work 우클릭 "Mermaid 불러오기" 제거됨
- IO 매핑은 동일 stem `*.iotag.json` 사이드카 — LLM 은 **PLC 주소 추론·생성 금지**

## Active / Passive 역할
- **Active** = 제어 로직 보유(제어를 *관장*). Project 당 **1개**(default Main). Flow/Work/Call 을 가짐.
- **Passive** = ApiDef 노출 디바이스(*피제어*). device 인스턴스마다 1개. Call 이 `<Passive>.<Api>` 로 호출.
- 같은 api 라도 **ApiDef 는 Passive 마다 별도**(공유 없음) — `Cyl1`/`Cyl2` 가 모두 ADV/RET 를 각자 선언하는 게 정상.

## Work 구성 (flow 당 최대 2개)
- robot 은 part 를 핸들링/이송하는 **공정 흐름 driver** → 독립 work `<Flow>_Robots`.
- 그 외 device(cylinder·clamp·gun·sealer 등)는 robot 동작에 종속·동기화되는 주변 액추에이터 → 한 묶음 work `<Flow>` (flow 명과 동일).
- 따라서 flow 당 work 는 robot 유무에 따라 1~2개. work 이름과 flow 이름이 같아도 충돌 없음(Flow·Work 는 별도 이름공간).
- **실행 순서 계층** — flow 간 순서는 flow(의 anchor work)를 잇는 `StartReset` arrow 가 **먼저 결정**한다(상위). call 의 `condition`(AutoAux 등)은 flow 간 순서를 정하는 게 아니라, 그 work 가 실행될 때 **work 내부 call 의 시작 조건**으로 동작한다(하위). 같은 flow 안 두 work(robot/나머지)는 `Group`(동시 시작 후보)이며 그 세부 선후도 call condition 이 부여.

## ArrowType 실행 의미
| Type | 의미 |
|---|---|
| `Start` | source 완료 → target 시작 |
| `Reset` | source 시작 → target 리셋 |
| `StartReset` | Start + 역방향 Reset |
| `ResetReset` | opposing 상호배타(둘 중 하나) — `opposing: chain` 이 자동 생성 |
| `Group` | group 으로 묶인 동일 node 동시 시작, 모두 종료후 다음 시작.  work 간, call 간 모두 허용 |

## Sibling Uniqueness
- 같은 부모 안 같은 종류 자식 이름은 unique: Project 하 System / System 하 Flow·Work / Passive 하 ApiDef. (work·flow 는 본 구조에서 **system 내 unique**.)
- **예외**: 같은 Work 안 같은 `<Passive>.<Api>` N회 = concurrent(동시 호출) 허용. 단 순차 chain(work `arrows:`)의 source/target 으로 중복 이름 참조는 모호 → 금지.
