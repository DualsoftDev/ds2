# DS 모델 도메인 배경

## Active / Passive 역할
- **Active** = 제어 로직 보유(제어를 *관장*). Project 당 **1개**(default Main). Flow/Work/Call 을 가짐.
- **Passive** = ApiDef 노출 디바이스(*피제어*). device 인스턴스마다 1개. Call 이 `<Passive>.<Api>` 로 호출.
- 같은 api 라도 **ApiDef 는 Passive 마다 별도**(공유 없음) — `Cyl1`/`Cyl2` 가 모두 ADV/RET 를 각자 선언하는 게 정상.

## ArrowType 실행 의미
| Type | 의미 |
|---|---|
| `Start` | source 완료 → target 시작 |
| `Reset` | source 시작 → target 리셋 |
| `StartReset` | Start + 역방향 Reset |
| `ResetReset` | opposing 상호배타(둘 중 하나) — `opposing: chain` 이 자동 생성 |
| `Group` | **UI 그룹 hint — 실행 시맨틱 없음** |

→ flow 내 work 를 전부 `Group` 으로 묶는 것은 "묶음 표시"일 뿐, **실제 실행 순서·동기화는 `Group` 이 아니라 call 의 `condition`(AutoAux/ComAux)이 담당**한다. work-arrow 로 순서를 표현하려 하지 말 것.

## Work 내부 call DAG (실행 의미)
- incoming `Start` 없는 call = **init call** → work 시작 시 즉시 실행. 복수면 동시 병렬.
- 같은 work 안 두 call 은 동시 going 불가(race-free 순차). 분기/합류 가능, **cycle 금지(DAG)**.

## 왕복은 같은 Work
- 같은 디바이스 인스턴스의 opposing 왕복(ADV↔RET, CLP↔UNCLP)은 **같은 Work 안 Call** 로 둔다.
- "전진 work / 후진 work" 로 분리 금지 — 다음 part 진입 시 디바이스가 이미 전진 상태라 ADV→ADV 자기이행 불가 → 라인 정지(capacity 충돌).

## 다중 선행 = AND
- `condition.conditions` 에 여러 `<Passive>.<Api>` 를 나열하면 **모두 완료되어야** 그 call 실행(OR 아님). 부품이 다 도착해야 조립되는 assemble 의미.

## Sibling Uniqueness
- 같은 부모 안 같은 종류 자식 이름은 unique: Project 하 System / System 하 Flow·Work / Passive 하 ApiDef. (work·flow 는 본 구조에서 **system 내 unique**.)
- **예외**: 같은 Work 안 같은 `<Passive>.<Api>` N회 = concurrent(동시 호출) 허용. 단 순차 chain(work `arrows:`)의 source/target 으로 중복 이름 참조는 모호 → 금지.
