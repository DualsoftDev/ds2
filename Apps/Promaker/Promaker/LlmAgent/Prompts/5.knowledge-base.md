# Knowledge Base 검색 결과 인용 룰

`attachment_search` / `attachment_read` 등 MCP tool 로 가져온 hit 를 응답에 인용할 때는 **반드시 아래 형식**을 따른다. UI 가 본 형식의 link 를 클릭 가능한 chip 으로 렌더하고, 클릭 시 hit 의 excerpt / outline 을 자동 표시한다.

## 인용 형식

    [<fileName>](attachment:///<fileId>/<ref>)

- `<fileName>` = `attachment_search` 결과의 `fileName` 필드. 사용자가 알아볼 수 있는 라벨.
- `<fileId>` = `attachment_search` 결과의 `fileId` 필드 *그대로*. 통상 `<collection-guid>:<document-id>` 형식 (콜론 포함) — 변형 / 축약 / URL-encoding 금지.
- `<ref>` = `attachment_search` 결과의 `ref` 필드 *그대로*. URL-encoding 추가 금지.
- **slash 3개 의무** (`attachment:///`) — 2개 (`attachment://`) 로 박제하면 fileId 의 콜론이 URL port 로 해석되어 UI 가 fileId 를 잘못 parse.

## 금지 사항

- `excerpt` / `outlinePath` / `score` 같은 hit 의 부가 정보를 응답 본문에 직접 인용하지 말 것. UI 가 link 클릭 시 자동으로 표시.
- `attachment:///` 외 임의 URI scheme (`http://` / `https://` / `file://` 등) 으로 hit 를 인용하지 말 것. UI 가 보안 차단함.
- 출처 없는 추정 문장 뒤에 link 를 붙이지 말 것 — link 는 실제 `attachment_search` hit 에서 *직접 도출된* 사실 옆에만 박제.

## 예시

답변 본문에 자연스럽게 link 박제:

> 모터 정격 전류는 12 A 입니다 [모터스펙.pdf](attachment:///3a7f1bcd-aaaa-bbbb-cccc-deadbeef0001:doc-42/p=4).
> 보호 등급은 IP65 입니다 [모터스펙.pdf](attachment:///3a7f1bcd-aaaa-bbbb-cccc-deadbeef0001:doc-42/p=7).

사용자가 link 를 클릭하면 UI 가 popup 으로 excerpt + outline 을 표시한다 — 응답 본문에는 본문 외 정보 미포함.

# 도면 / 이미지 추궁 룰 (Phase 2, s6-r20 박제)

`attachment_search` hit 의 `hasImages=true` 는 해당 chunk 가 도면 / 그래프 / 표 등 raster 이미지를 포함한다는 의미 (Chunks.ImageCount > 0 정합). 텍스트 만으로 사양을 답할 수 없는 경우 (e.g. "이 wiring diagram 에서 CV01 단자 위치는?") 다음 우선순위로 `attachment_read` 호출:

1. **`attachment_read(fileId, ref, includeImages=false, captionOnly=true)` 우선** — 색인 시점에 생성된 VLM caption (`이 이미지를 한국어로 1~2문장 ... 도면/표/그래프인 경우 안에 보이는 라벨/번호 우선 인용`) 만 반환. 응답 token 가벼움, 대부분의 추궁이 caption 으로 해결.
2. **caption 만으로 부족 시 `includeImages=true`, `captionOnly=false`** — text + base64 image content block 동봉. 단 size 가드:
   - 단일 image > ~3.75MB → 자동 skip + `[oversize_image_count=N, max_single_bytes=M — skipped]` marker
   - 응답 image 수 > 5 → 자동 `caption_only` 강등 + `[oversize_image_count=N, max=5 — auto caption_only degrade]` marker
   - 즉 `includeImages=true` 박제해도 정책상 caption_only 로 강등될 수 있음.
3. **`captionOnly=true` 와 `includeImages=true` 동시 박제 시 captionOnly 우선** (image binary 미동봉). image binary 가 *반드시* 필요한 경우 `captionOnly=false` 명시.

`includeImages=false, captionOnly=false` 조합은 ambiguous — server 가 audit warn + caption_only fall-back. 두 flag 중 *하나는 명시* 의무.

quota 가드: tool wrapper 가 `maxExcerptTokens=4000` / `maxCumulativeTokens=16000` enforce. 큰 도면 다중 동봉 시 token 가드에 먼저 걸릴 수 있음.

# 전체 본문 fallback (`attachment_fulltext`)

`attachment_search` hit 의 excerpt 만으로 부족한 경우 (예: 전체 절차 / 긴 도면 caption 종합 / 다중 chunk 가 한 문서를 분산) 의 fallback 으로 `attachment_fulltext(fileId)` 를 호출. 응답은 색인 시점 생성된 markdown text dump (`.lighthouse-kb/text/<docId>-<filename>.md`) 의 streaming text — 단일 호출 ≤ 1 MB 가드.

- 우선순위: `attachment_search` → 부족 시 `attachment_fulltext`. 첫 호출부터 fulltext 사용은 token 과잉 박제 risk.
- legacy collection (text/ 폴더 부재) 은 빈 string 반환 — caller 가 search excerpt fallback.
