2. 알고리즘 게이팅 파이프라인

입력: (aTimes, bTimes, config, declaredKind, logicStrength?)
  │
  ├─ low_n check                                  → Reason "low_n"
  ├─ sufficiency / necessity                       (basic pair matching)
  ├─ Outlier filter (Tukey IQR) ★ B4.2             — lag outliers 제거
  ├─ lag stats (mean / std / cv / abs)
  │
  ├─ Mode count (75ms bin histogram) ★ Phase 1     — multi-modal 거부 기준
  ├─ Stability gates (OR 결합):
  │     • lag cv ≤ 0.30
  │     • smallLagFallback (lagMean<150 AND lagStd 적절) ★ tighten
  │     • bimodalStable (gap≥100, std<60, 25%/75%) ★ relax
  │     • driftStable (linear regression)
  │     • cyclicStable (autocorrelation + cos/sin fit) ★ B1.1
  │
  ├─ Gate dispatch:
  │     • declared "group"   → passes_grp 검사 → EmitGroup
  │     • declared "reset"   → cycle hint 비활성 ★ B3.1
  │     • declared "mutex"   → mutexScore (co-occurrence) ★ B3.2
  │     • declared "trigger" → passes_seq 검사 → EmitSequential
  │
  ├─ Cluster mode fallback                         (multi-source 시)
  │
  └─ Confidence calculation ★ B2:
        score = primary * 0.7 + logic * 0.3 (hybrid) ★ B5
        nReliability = f(NA)
        tier = High / Medium / Low / Reject ★ B2.2

6. 본질적 한계 (Out-of-Scope)

  • Multi-modal 3+ 인과 — 현재 거부. 진짜 5-modal queue (q4) 같은 경우 알고리즘적 한계.
  • Polling vs causation 분리 — POLL 이 actual fire 와 무관해도 매번 직전 발화 → 통계적 인과 처럼 보임.
  • Hidden confounding variables — 외부 timer 같은 측정 불가 변수.
  • Real-time learning — Online detection 후 weight 자가 조정은 강화학습 영역.
